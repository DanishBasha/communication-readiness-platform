## 🎯 Key Features

### Data Structure
```
Key: topic:cache:{normalized_topic}
Value: {
  topic: "system design",
  items: [
    {
      question: "What is meant by system design?",
      rubric: { criteria: [...], maxScore: 10 },
      difficulty: "EASY",
      createdAt: "2026-10-06T10:30:00.000Z"
    },
    ...
  ],
  lastUpdated: "2026-10-06T10:30:00.000Z"
}
```

### Cache Behavior
- **Storage**: Redis with configurable TTL (default: 7 days)
- **Organization**: Questions grouped by extracted topic
- **Filtering**: Retrieve by difficulty level (EASY, MEDIUM, ADVANCED)
- **Normalization**: Topics normalized to lowercase for consistency
- **Multi-user**: Shared across all users and sessions

### Automatic Caching
- Questions are **automatically cached** when generated by LLM
- Topic is **extracted** from question text
- Cache writes are **non-blocking** (don't affect interview flow)
- Failures are **logged** but don't break functionality

## 🔌 API Endpoints

| Method | Endpoint | Auth | Description |
|--------|----------|------|-------------|
| GET | `/api/topic-cache` | User | List all cached topics |
| GET | `/api/topic-cache/:topic` | User | Get questions for a topic |
| GET | `/api/topic-cache/:topic/stats` | User | Get cache statistics |
| GET | `/api/topic-cache/:topic/random` | User | Get random question (with difficulty filter) |
| POST | `/api/topic-cache` | Admin/Trainer | Manually add question |
| DELETE | `/api/topic-cache/:topic` | Admin | Clear specific topic |
| DELETE | `/api/topic-cache` | Admin | Clear all caches |
| PATCH | `/api/topic-cache/:topic/ttl` | Admin | Update cache TTL |

```bash
curl -H "Authorization: Bearer <token>" \
  "http://localhost:5001/api/topic-cache/system%20design/random?difficulty=EASY"

# Response:
{

    "maxScore": 10

  "difficulty": "EASY",
  "createdAt": "2026-10-06T10:30:00.000Z"

```

### Check cache before generating
```typescript
import { topicCacheService } from '../services/topicCacheService';

// Try cache first
const cached = await topicCacheService.tryGetCachedQuestion('system design', 'EASY');

if (cached) {
  // Use cached question
  const { question, rubric } = cached;
} else {
  // Generate via LLM and cache automatically
  const generated = await generateViaLLM('system design', 'EASY');
  await topicCacheService.addToCache('system design', generated.question, generated.rubric, 'EASY');
}
```

Default: 7 days (604800 seconds)

Customize in `topicCacheService.ts`:
```typescript
private readonly DEFAULT_TTL_SECONDS = 604800;
```

Or per-cache via API:
```bash
curl -X PATCH \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{"ttlSeconds": 1209600}' \
  http://localhost:5001/api/topic-cache/system%20design/ttl
```

## 🎓 How It Works

### Automatic Flow
1. **Interview**: Student answers question
2. **LLM Evaluation**: Generate next question + rubric
3. **Topic Extraction**: Extract topic from question text
4. **Cache Write**: Store question-rubric pair (background, non-blocking)
5. **Future Use**: Other sessions can retrieve cached questions

### Manual Flow
1. **Admin**: POST to `/api/topic-cache` with topic, question, rubric
2. **Cache**: Stores with specified TTL
3. **Users**: GET from `/api/topic-cache/:topic/random` to retrieve
