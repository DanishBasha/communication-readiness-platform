# Persistent Topic Cache Implementation

## Overview

This implementation adds a **persistent cache layer** that stores topics, questions, and rubrics generated by the LLM. Unlike the existing session-based cache, this cache:

- ✅ Persists across sessions
- ✅ Is reusable by multiple users
- ✅ Has configurable TTL (Time-To-Live) for automatic expiration
- ✅ Stores questions and rubrics as lists indexed by topic
- ✅ Does not break existing functionality

## Implementation Details

### 1. Topic Cache Service (`topicCacheService.ts`)

**Core Features:**
- **Topic Extraction**: Automatically extracts topics from questions
- **Normalized Storage**: Topics are normalized (lowercase, trimmed) for consistency
- **TTL Management**: Default 7 days, configurable per cache
- **Difficulty Filtering**: Store and retrieve by difficulty level
- **List Storage**: Questions and rubrics stored as lists, not single values

**Key Methods:**

```typescript
// Add a question-rubric pair
await topicCacheService.addToCache(
  'system design',           // topic
  'What is meant by...',     // question
  { criteria: [...] },       // rubric
  'EASY',                    // difficulty
  604800                     // TTL in seconds (optional)
);

// Get cached questions for a topic
const cache = await topicCacheService.getFromCache('system design');
// Returns: { topic, items: [{question, rubric, difficulty, createdAt}], lastUpdated }

// Get a random question for a topic with difficulty filter
const pair = await topicCacheService.getRandomPair('system design', 'EASY');
// Returns: { question, rubric, difficulty, createdAt }

// Check cache statistics
const stats = await topicCacheService.getCacheStats('system design');
// Returns: { exists, itemCount, byDifficulty: {EASY: 5, MEDIUM: 3}, lastUpdated }

// Extract topic from a question
const topic = topicCacheService.extractTopicFromQuestion('What is system design?');
// Returns: 'system design'
```

### 2. Integration with LLM Evaluation

The cache is **automatically populated** when the LLM generates questions during interviews:

**File:** `backend/src/services/llmEvaluationService.ts`

```typescript
// After LLM generates next question and rubric
if (raw.next_question_text && raw.rubric_for_next_question) {
  const extractedTopic = topicCacheService.extractTopicFromQuestion(raw.next_question_text);
  if (extractedTopic) {
    // Non-blocking background cache write
    topicCacheService
      .addToCache(
        extractedTopic,
        raw.next_question_text,
        raw.rubric_for_next_question,
        nextDifficulty
      )
      .catch((err) => {
        console.error('[llmEvaluation] Topic cache write failed:', err);
      });
  }
}
```

**Key Points:**
- ✅ Non-blocking: Cache failures don't affect interview flow
- ✅ Automatic: No manual intervention needed
- ✅ Smart extraction: Topic extracted from question text
- ✅ Preserves existing behavior: Session cache still works as before

## Data Structure

### Redis Storage Format

**Key Pattern:** `topic:cache:{normalized_topic}`

**Example:**
```
Key: topic:cache:system design

Value (JSON):
{
  "topic": "system design",
  "items": [
    {
      "question": "What is meant by system design?",
      "rubric": {
        "criteria": ["Understanding of concepts", "Clarity of explanation"],
        "maxScore": 10,
        "passingScore": 6
      },
      "difficulty": "EASY",
      "createdAt": "2026-10-06T10:30:00.000Z"
    },
    {
      "question": "Explain the principles of scalable system design",
      "rubric": { ... },
      "difficulty": "MEDIUM",
      "createdAt": "2026-10-06T11:15:00.000Z"
    }
  ],
  "lastUpdated": "2026-10-06T11:15:00.000Z"
}
```

### Topic Normalization

Topics are normalized before caching:
- `"System Design"` → `"system design"`
- `"  data structures  "` → `"data structures"`
- `"Binary   Search"` → `"binary search"`

This ensures cache hits even with slight variations in capitalization or spacing.

### Coexistence with Session Cache

| Feature | Session Cache | Topic Cache |
|---------|--------------|-------------|
| Purpose | Turn-by-turn context | Question reuse |
| Scope | Single session | Global |
| Lifetime | 2 hours | 7 days (configurable) |

| Key | `session:{sessionId}:context` | `topic:cache:{topic}` |

Both caches **work together**:
- Session cache: Stores interview context for ongoing sessions
- Topic cache: Stores reusable questions across all sessions

## Usage Examples

### Example 1: Check Cache Before Generation

```typescript
import { topicCacheService } from '../services/topicCacheService';

async function getQuestion(topic: string, difficulty: 'EASY' | 'MEDIUM' | 'ADVANCED') {
  // Try cache first
  const cached = await topicCacheService.tryGetCachedQuestion(topic, difficulty);

  if (cached) {
    console.log('✓ Cache hit!');
    return cached;
  }

  // Cache miss - generate via LLM
  console.log('✗ Cache miss - generating via LLM');
  const generated = await generateViaLLM(topic, difficulty);

  // Cache for future use
  await topicCacheService.addToCache(
    topic,
    generated.question,
    generated.rubric,
    difficulty
  );

  return generated;
}
```

## Performance Considerations

### Benefits
- 🚀 **Faster response times**: Cache hits return instantly
- 💰 **Cost savings**: Reduced LLM API calls
- 📊 **Consistent questions**: Topics generate similar questions over time
- 🔄 **Reusability**: Multiple users benefit from same cached questions

### Trade-offs
- 💾 **Redis memory**: Each question-rubric pair consumes memory
- ⏱️ **Freshness**: Cached questions may become outdated (mitigated by TTL)
- 🎯 **Extraction accuracy**: Simple topic extraction may miss nuances

### Monitoring

Monitor Redis memory:
```bash
redis-cli INFO memory
```

Track cache metrics:
- Cache hit rate
- Cache size per topic
- Memory usage trends

## Troubleshooting

### Cache Not Working

1. **Check Redis connection**:
   ```bash
   redis-cli ping
   # Should return: PONG
   ```

2. **Verify REDIS_URL in .env**:
   ```env
   REDIS_URL=redis://localhost:6379
   ```

3. **Check logs** for cache-related errors:
   ```bash
   grep "TopicCache" backend/logs/*.log
   ```

### Cache Miss Rate Too High

- Review topic extraction logic
- Check if topics are being normalized correctly
- Consider pre-warming cache for common topics

### Redis Memory Issues

- Reduce TTL for less important topics
- Implement cache size limits
- Clear old/unused caches periodically
